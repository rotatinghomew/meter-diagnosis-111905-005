# 活动室运行与排期

本项目整理社区服务运营的合成数据，判断哪些房间组合可以长期预约，并支撑第 11–15 日排期。
`fixtures/` 保存本地合成源记录，各表字段和业务时序约定见 `DATA.md`。没有线上服务或真实个人信息。

## 目录

- `roomload/`：分析包
  - `loading.py`：CSV 读取与校验，应用 `supersedes` 替代链
  - `events.py`：转态事件 → 每个试运行 block 的事实时间线（时钟不确定下保留全部相容解释）
  - `metrics.py`：点位覆盖、超线分钟比例、同日同设备基线、increase_cap 判定
  - `licensing.py`：房间组合 × 门状态 × 设备状态的确认/拒绝/未知结论、K2-2 归因、反事实对照
  - `scheduling.py`：预约窗口评估、志愿值守/借道通行约束、临时换房三要素
  - `report.py`：Markdown 与 JSON 报告渲染
- `reports/`：运行后生成的报告（许可表、K2-2 归因、排期决定、反事实对照、results.json）
- `tests/`：源记录结构测试（`test_fixtures.py`）与业务规则测试（`test_analysis.py`）

## 使用

需要 Python 3.11。按隔离模式运行（不读取环境中的第三方模块）：

```sh
# 生成报告到 reports/
python3 -I run_analysis.py fixtures reports

# 运行全部测试
python3 -I run_tests.py
```

## 口径要点

- 干扰指标 = 点位读数达到 cutoff 的分钟 / 该点位组**已覆盖**分钟；未覆盖不等于零，室内点与走廊点不互代。
- 增量上限只与**同日、同设备状态的无活动 block**比较；缺这种基线或覆盖不足的条件标“未知”，
  不能用白天设备关闭的观测替代设备开启的基线。
- 关门是必须由现场人员落实的条件（同一人同一时刻只能负责一扇门，借道通行时段不得闭门），不是预约备注。
- 单房间合格不等于相邻房间能同时排；受控试用不得抢占已确认活动、不得伪装成正式开放。
- 后补记录只缩小有效区间、不删除整个配对批次；已执行活动只能更正归因，不能重记成未发生。
